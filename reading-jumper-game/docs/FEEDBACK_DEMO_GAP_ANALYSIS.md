# 客户 Demo 正负反馈严格复现规格

## 1. 结论

当前两个游戏的正负反馈还不能称为“严格还原 Demo”。已解决的 WebP 宽高比、抽帧和过度缩放问题，只解决了失真，不等于还原了 Demo 的动作编排。

严格还原的核心不是继续放大一段人物 WebP，而是把每次答题实现为一条完整事件链：

`移动到选项 -> 接触选项 -> 选项状态变化 -> 主体/道具进入 -> 命中 -> 人物受力或庆祝 -> 粒子与音效 -> 最终状态 -> 切题`

当前最重要的结论如下：

1. 客户提供的 20 套正/负人物序列全部有透明通道，尺寸和人物主体可直接使用。
2. 多数人物序列只包含“人物反应”，Demo 中的炸弹、墨鱼、毛笔/投射物、爆炸、沙柱、龙卷风等是另外的舞台事件，不能把人物序列当成完整反馈。
3. 客户完整切图中已有炸弹、墨鱼喷水、毛笔、白鹤、宝箱/蛋/莲花/魔法书的结果态等关键单图，可以先通过位移、缩放、旋转、遮挡和粒子补间完成高还原版本。
4. 星际穿越的负反馈不是“黑洞吸入”。本 Demo 中是角色跳向右侧选项后，火箭/太空物体从上方落下，最终角色站在坠落物旁。
5. 诗词山水的负反馈不是“墨迹覆盖”。本 Demo 中是角色跳向右侧选项，投射物从上方落下并命中，角色倒地。
6. 阅读游戏当前的全屏黑色遮罩和通用弹出缩放与 Demo 冲突，必须移除。
7. 写作游戏当前把五个场景套进同一套 `castAt -> reveal -> feedback` 流程，无法还原每个场景不同的下降、挖掘、爆炸、追逐和卷起过程。
8. PNG 序列本身不携带帧率元数据。当前统一按 24fps 导出只是实现假设，严格还原时必须以 Demo 关键帧反推每套动画的播放时长，不能继续全局写死 24fps。

第一阶段不需要等待客户补素材。现有素材足以完成结构、位置、时序和大部分效果。只有在逐帧截图验收后，确认单图补间无法达到轮廓一致的特效，才请求客户补透明序列。

### 2.3 测量方法与精度

1. 视频先按 1fps 做全片场景定位，再按每 5 帧做动作阶段分解。
2. 第 11 节列出的视觉关键帧已回到恒定 30fps 原片，在候选边界前后逐帧确认。
3. 关键音效使用客户 MP3 与 Demo 音轨做波形互相关，得到毫秒级候选起点；音频候选换算到最近的视频帧后仍需结合波形复核。
4. 坐标统一以 Demo 的 `1920x1080` 左上角为原点。
5. 当前游戏设计舞台为 `1440x810`，与 Demo 同为 16:9。坐标换算为：

```text
demoX = designX * 1920 / 1440
demoY = designY * 1080 / 810
```

6. 音频相关置信度低于 0.5 的时间只作为定位候选，必须以画面和波形再次确认。基础宝藏负反馈音效相关结果无效，不能直接写进代码。

## 3. 严格还原的全局规则

### 3.1 舞台与适配

- 背景可以使用 `cover` 横向铺满。
- 人物、恐龙、火箭、宝箱、蛋、莲花、书本和特效必须统一等比缩放。
- 动画舞台使用 16:9 安全舞台 `contain`，超宽屏只增加两侧背景，不横向拉伸角色。
- 选项锚点必须跟随背景裁切后的实际列位置，不能只使用固定屏幕百分比。
- 人物脚底、恐龙脚底和地面线在任意宽屏下误差不得累积。

推荐坐标变换：

```text
uniformScale = viewportHeight / 810
stageWidth = 1440 * uniformScale
cropOffsetX = (viewportWidth - stageWidth) / 2
screenX = cropOffsetX + designX * uniformScale
screenY = designY * uniformScale
```

如果背景为了铺满额外横向缩放，选项列应由背景中的实际洞/砖块/书本节点提供，而不是把人物层一起乘 `backgroundScaleX`。

### 3.2 人物所有权交接

- 触发前由游戏常驻人物节点负责跑、跳、下降或施法。
- 只有当反馈序列首帧人物姿态与常驻人物同帧重合时，才隐藏常驻人物。
- 反馈动画结束后，不应闪回待机人物；应直接保留终态或进入转场。
- 不允许“常驻人物先消失，反馈人物随后在另一个位置弹出”。

### 3.3 图层顺序

通用顺序：

```text
背景
场景后景
选项/洞/砖块后层
人物后方特效
人物或载具
命中主体
烟雾/墨汁/沙尘/龙卷风前层
洞口、蛋壳、书本等前景遮挡
金币与庆祝粒子
HUD、题干、摄像头
```

HUD 不参与场景缩放，不被墨汁、爆炸、龙卷风或黑色遮罩覆盖。

### 3.4 时间与音效

- 所有关键事件以时间轴数据驱动，不在控制器里散落多个独立 `delay`。
- 音效绑定到“接触、裂开、爆炸、落地、卷起、金币到达”等关键帧。
- 视觉与音效允许误差：`<= 40ms`。
- 关键动作与 Demo 允许误差：`<= 1 个 30fps 视频帧，即 33.3ms`。
- 下一题只能在主体动画、前景特效和最后音效全部结束后开始。

### 3.5 禁止的通用效果

以下效果不在 Demo 中，不能继续套用：

- 全屏 `rgba(5, 8, 11, 0.8)` 黑色反馈遮罩。
- 所有反馈统一 `0.78 -> 1.10 -> 1.00` 或 `0.88 -> 1.00` 的弹出缩放。
- 反馈开始时统一淡入。
- 所有场景统一使用一个固定反馈框。
- 人物反馈开始后再播放攻击主体，造成因果顺序倒置。

## 4. 当前代码的全局阻断点

### 4.1 阅读跳跳乐

涉及文件：

- `assets/scripts/ui/FeedbackView.ts`
- `assets/scripts/games/reading-jumper/controllers/ReadingAnswerController.ts`
- `assets/scripts/games/reading-jumper/config/ReadingLayout.ts`
- `assets/scripts/core/media/MotionPlayback.ts`

阻断点：

1. `FeedbackView.ensureUnderlay()` 创建全屏 80% 黑色遮罩，Demo 全程保持场景明亮。
2. `FeedbackView.show()` 对所有场景执行通用弹出缩放，破坏火箭坠落、墨鱼下降、投射物命中等真实运动。
3. `ReadingAnswerController` 等待人物落地和金币到达后才 `showFeedback()`。Demo 的正负反馈与跳跃命中连续发生，不能在落地后另起一段贴纸动画。
4. 当前反馈只按选中列设置一个局部 WebP，无法表现从画外进入的墨鱼、投射物和飞行主体。
5. `MotionPlayback.ts` 只记录打包 WebP 时长，不记录 Demo 的跑动、命中、道具进入和收尾阶段。

### 4.2 写作宝藏

涉及文件：

- `assets/scripts/games/writing-treasure/controllers/TreasureInteractionController.ts`
- `assets/scripts/shared/config/WritingFeedbackPolicy.ts`
- `assets/scripts/ui/FeedbackView.ts`
- `assets/scripts/ui/FeedbackLayerView.ts`
- `assets/scripts/ui/FeedbackStageMotionView.ts`
- `assets/scripts/core/media/MotionPlayback.ts`

阻断点：

1. 五个场景都先执行通用 `castAt()`，但 Demo 中分别是挖掘、下沉、飞行下降、蛋洞挖掘和施法。
2. `WritingActionTiming` 使用固定 `holdMs` 和三次通用敲击点，不对应源序列关键帧。
3. `showFeedback()` 前直接 `this.view.deer.hide()`，容易造成反馈人物位置跳变。
4. `FeedbackView` 对局部反馈执行通用 `0.88 -> 1.00` 弹出。
5. `FeedbackLayerView` 使用 `fit: 'fill'`，会在配置框与素材比例不同时拉伸图层。
6. 当前静态层大多是最终状态，不是完整运动过程。
7. 当前场景顺序是 `treasure -> desert -> dinosaur -> dunhuang -> magic`，Demo 是 `treasure -> desert -> dunhuang -> dinosaur -> magic`。如果客户要求整片流程一致，需要同步调整顺序。

## 8. 阅读跳跳乐逐场景规格

### 8.1 马里奥

正反馈阶段：

1. 人物跑到选中砖块下方。
2. 人物起跳，头部在 `9.629s` 对应帧命中砖块底部。
3. 被选砖块切换选中/正确状态。
4. 金币从砖块中心上沿弹出，`9.928s` 播放金币音效。
5. 人物落地后接正反馈人物序列，不改变脚底 X。
6. `11.363s` 播放正确音效，随后出现彩纸，场景保持明亮。

负反馈阶段：

1. 人物跑到错误砖块下方并起跳。
2. 炸弹在 `16.896s` 从砖块上方出现并向下落。
3. 炸弹命中/爆炸中心与砖块中心一致。
4. 爆炸先遮挡人物，再切换到眩晕人物序列。
5. `18.429s` 播放错误音效，人物蹲下保持约一个节拍后切题。

当前差距：

- 当前反馈在落地和金币到达后才显示，事件链被拆断。
- 缺少炸弹下落、爆炸前景和彩纸时间轴。
- 全屏黑色遮罩完全不符合 Demo。

### 8.2 深海龙宫

正反馈：

- 人物跳向左侧目标。
- 金币从选项附近上升。
- 人物落地后播放庆祝序列，脚底保持海床线。
- 主音效起点为 `30.681s`。

负反馈：

1. 人物移动并跳向右侧目标。
2. 墨鱼从画面右上边界外进入，路径为左下方向。
3. 墨鱼逐渐放大并落到人物上方。
4. 墨汁前层覆盖人物脸和上身，但不覆盖题干与 HUD。
5. 墨鱼离开或淡出，留下负反馈人物的墨汁终态。
6. 主音效起点为 `38.748s`。

当前差距：

- 现有负反馈 WebP 只有被墨后的角色，没有墨鱼进入和压下过程。
- `墨鱼喷水.png` 可先作为独立主体做路径补间；严格逐帧验收不过时再补墨鱼透明序列。

### 8.3 星际穿越

正反馈：

1. 人物跳向左侧选项，星星从人物运动方向向后拖尾。

## 11. 每套反馈的 30fps 关键帧时间表

### 11.1 统一口径

1. 帧号从 `F0` 开始，时间换算为 `time = frame / 30`。
2. 每张表的 `T0` 是该反馈中第一个可稳定用于代码同步的结果事件，不是用户点击、语音识别完成或控制器开始执行的时刻。
3. `逐帧实测` 表示已在原始 30fps 视频的候选边界前后逐帧检查首个可见变化。
4. `音频候选` 表示由波形互相关或现有主音效定位换算到最近视频帧，实施前仍需核对波形；不能覆盖视觉实测结论。
5. 相对时间允许出现负值，表示 T0 之前必须已经开始的助跑、下降、挖掘或施法。
6. 表内时间是客户 Demo 的全局时间。正式代码应保存相对帧，不应直接依赖整片视频时间。

- 代码配置使用整数 `relativeFrame`，运行时再换算为毫秒；不要把本文三位小数时间重新四舍五入后写回配置。
- 视觉首帧优先级高于音频候选。若音效候选与视觉事件相差超过 1 帧，应先确认音效语义，不允许强行把主体动画拖到音频点。
- 角色交接帧必须同时校验常驻人物与反馈人物的脚底、中心 X、朝向和姿态，不能只按透明画布中心对齐。
- `transition.enter` 是 Demo 参考，不等于游戏必须在该帧切题；主体、前景特效、积分金币和最后音效未结束时必须延后。
- 实现完成后，每张表至少对 `T0`、主体首次进入、命中峰值、终态和转场前五个节点输出自动截图。

## 12. 推荐实现结构

### 12.1 数据结构

每个场景、每个正负反馈使用独立配置：

```ts
interface FeedbackTimelineSpec {
  sceneId: string;
  result: 'correct' | 'wrong';
  referenceSize: { width: 1920; height: 1080 };
  targetColumns: readonly [number, number, number];
  groundY: number;
  phases: readonly {
    id: string;
    startMs: number;
    durationMs: number;
    layer: string;
    asset?: string;
    from?: { x: number; y: number; scale?: number; rotation?: number };
    to?: { x: number; y: number; scale?: number; rotation?: number };
    audio?: string;
    hideAtEnd?: boolean;
  }[];
}
```

### 12.2 渲染节点

至少拆成：

- `stageBackground`
- `choiceBack`
- `actor`
- `effectBack`
- `impactActor`
- `effectFront`
- `choiceFront`
- `rewardParticles`
- `hud`

每个节点都有自己的等比布局和 zIndex，不能继续依赖一个通用反馈 WebP 容器。

### 12.3 序列导出

1. 不从文件数量直接推断帧率。
2. 先在 Demo 中确定序列首帧和末帧时间，再计算每帧时长。
3. 保留原始宽高比和透明边缘。
4. 关键人物/特效优先使用无损 WebP；若体积超限，再使用高质量有损并做边缘差分检查。
5. 禁止先裁透明边再放大到固定反馈框。
6. 动画只播放一次，最后一帧是否保留由场景时间轴决定。

## 14. 自动验收标准

### 14.1 参考尺寸

至少回归：

- 1920x1080：客户 Demo 基准。
- 1440x810：设计舞台。
- 915x412：常见小程序横屏。
- 2271x960：超宽横屏。

### 14.2 像素与路径

- 选项触发中心误差：`<= 8px`，按 1920x1080 计。
- 人物脚底和地面线误差：`<= 6px`。
- 人物/道具宽高比例误差：`<= 1.5%`。
- 运动路径关键点 RMS 误差：`<= 8px`。
- 恐龙追逐中，人物最后可见像素必须跨过右边界后才隐藏。
- 从画外进入的主体，第一帧可见像素必须位于边界上或边界外，不允许在画面内部突然出现。

### 14.3 时间与音频

- 命中、爆炸、开箱、卷起等关键帧误差：`<= 33.3ms`。
- 音效与视觉关键帧误差：`<= 40ms`。
- 动画不得提前切题。
- 不允许重复循环人物最后一段动作。

### 14.4 图像质量

- 背景静态区域 SSIM：`>= 0.97`。
- 人物/特效 alpha 轮廓 IoU：`>= 0.92`。
- 透明边缘不得出现黑边、白边和明显色溢。
- 除背景外，任意人物和道具节点的 `scaleX / scaleY` 差值应小于 `0.01`。
- HUD、题干和摄像头区域不参与场景特效遮挡。

### 14.5 截图证据

每个正负反馈至少固定输出六张：

1. 触发前。
2. 接触选项帧。
3. 主体首次进入帧。
4. 命中峰值帧。
5. 人物最终状态帧。
6. 离场/切题前最后一帧。

最终验收不能只看动画是否播放，必须把上述截图与 Demo 同时间码并排比较。

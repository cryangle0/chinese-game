# 阅读跳跳乐负反馈特效修订设计

## 目标

本次只修订开发版的四项视觉问题：

1. 超级玛丽答错时，炸弹抵达积分区域的终点爆炸不够明显。
2. 深海龙宫答错时，缺少墨鱼喷墨过程；保留现有人物负反馈并叠加墨鱼序列帧。
3. 美食大冒险待机人物脚底悬空。
4. 诗词山水答错飞行物必须使用客户提供的纯毛笔素材，墨水只在积分终点生成。

不改题库、计分规则、答题时序、结算、分享、摄像头姿态逻辑，也不发布体验版或正式版。

## 已确认根因

### 炸弹终点

`ScoreCoinDom.spawnScoreTerminalEffect()` 当前为 `explosion` 生成约 70 设计像素的圆形径向渐变。图1参考效果是明显的红色爆云、白黄中心闪光和外扩轮廓，因此当前终点尺寸与形状都偏弱。

### 深海喷墨

`ReadingScoreFeedback` 的 `deep-sea` 只有正反馈道具，没有负反馈道具。答错链路只触发通用顶部滴落和 `wrong.webp` 人物反馈，未加载客户的墨鱼序列帧。

客户素材 `墨鱼喷汁雪碧图.png` 为 1536×1024 的非规则排布图，不是可按固定行列直接切割的标准雪碧图。按实际主体组件识别，共 26 帧，分行为 9、7、5、5 帧；后半段包含与主体分离的墨滴。直接按 8×4、10×4 或 12×4 切割都会截断主体或墨滴。

### 美食人物落地

开发版实测待机人物脚底距平台约 7 屏幕像素，折合约 10 设计像素。当前 `ReadingLayout.food.deer.y` 为 `-225`；待机图 16 帧还包含 2–12 像素不等的透明底边，因此视觉上持续悬空。

### 诗词毛笔

当前 `customer-media/reward-props/poetry/penalty.png` 已把毛笔与墨花合成在一张图中。客户指定的新素材 `负反馈-金币素材.png` 是纯毛笔，要求飞行阶段只显示毛笔，抵达积分区域后再生成墨水效果。

## 方案选择

采用“主题化独立特效”：

- 保留现有 `ScoreCoinEffectView` 飞行与目标定位。
- 玛丽和诗词只扩展终点效果，不合成新的整段 WebP。
- 深海新增独立的高层 DOM 序列帧播放器，叠加在现有 DOM 人物反馈上方。
- 美食只修改该主题的角色落地坐标。

不采用合成整段 WebP，因为三列答题位置不同，重新出片无法可靠跟随人物；不采用纯 CSS 墨鱼，因为必须忠实使用客户素材。

## 详细设计

### 1. 玛丽炸弹终点爆炸

炸弹飞行轨迹、尺寸和旋转保持不变。抵达 `HudView.scoreRewardTarget()` 后生成以下层次：

1. 170×150 设计像素的红色多瓣爆云，中心锁定积分目标；
2. 92×92 的白黄八角闪光；
3. 一道橙红扩散环；
4. 12–16 个红黄碎片；
5. 总时长约 700ms，前 180ms 达到峰值，再快速消散。

爆炸位于 HUD 上方但不改变积分文本和计分时机。终点仍由现有 stage-to-screen 转换计算，避免不同屏幕比例下漂移。

### 2. 深海墨鱼喷墨

#### 素材构建

新增确定性资产构建脚本：

- 读取客户原图 RGBA，不改变源文件。
- 按四个内容行识别 9/7/5/5 个主体连通区。
- 每帧以最大主体连通区为墨鱼主体，并将分配给该帧的邻近独立墨滴一起纳入。
- 保留原始像素，不插值缩放。
- 以主体右边缘和顶部作为稳定锚点，将 26 帧重排到 256×256 等尺寸帧格。
- 输出到 `customer-media/reward-props/deep-sea/ink-squid-sheet.png`，由高层 DOM 播放器通过 `/media/` 加载；不生成无用的 Cocos `.meta`。

构建测试必须验证：源图 1536×1024、帧数 26、行分布 9/7/5/5、输出每帧 256×256、最后喷墨帧保留独立墨滴。

#### 播放与位置

新增专用 DOM 序列帧视图，层级高于 `FeedbackView` 的 DOM 动画：

- 在深海答错人物反馈 `onReady` 后开始，避免墨汁先于人物出现。
- 15fps，26 帧，单次播放约 1.73 秒。
- 根据所选列动态定位，不写死左/中/右屏幕坐标。
- 墨鱼主体位于人物头部右上方，喷射方向朝左下。
- 人物头部命中点取当前所选列中心与深海负反馈可见头部中心；开发版实测参考点为屏幕设计坐标 `(720 + columnX, 375)`。
- 序列帧容器初始中心约为命中点右移 90、上移 75 个设计像素；最终以左、中、右三列截图校准，使主要墨流覆盖额头/头冠区域，不喷到题板或 HUD。
- 播放结束移除 DOM 节点；下一题、场景切换和视图销毁必须立即清理。

现有被墨汁淋中的人物 `wrong.webp` 和顶部背景滴落继续保留。

### 3. 美食人物落地

将 `ReadingLayout.food.deer.y` 从 `-225` 调整为 `-235`，其余场景不变。

验收 16 帧待机循环：

- 脚底不得高于平台超过 2 屏幕像素；
- 不得穿入平台超过 2 屏幕像素；
- 左右跑动和起跳仍从同一基线开始。

### 4. 诗词毛笔与终点墨水

资产处理：

- 以客户 `负反馈-金币素材.png` 为唯一毛笔来源；
- 裁去透明边缘后按比例生成紧凑 PNG，不预合成墨花；
- 飞行显示尺寸维持约 94×105 设计像素，保留当前轻微旋转。

抵达积分目标后生成：

1. 约 110×82 的主墨团；
2. 18 个不同尺寸、椭圆度和方向的墨滴；
3. 一道低透明度淡墨扩散环；
4. 约 800ms 后全部消失。

墨团中心与积分目标一致，不把墨水画进毛笔素材，也不改变扣分时机。

## 代码边界

- `ReadingScoreFeedback.ts`：只维护各主题飞行物与终点类型。
- `ScoreCoinDom.ts`：负责爆炸和终点墨水的 DOM 图形。
- 新的深海喷墨视图：只负责 26 帧播放、坐标转换和清理。
- `ReadingAnswerController` / `ReadingGameView`：只在深海答错人物反馈就绪后触发喷墨。
- `ReadingLayout.ts`：只调整美食角色基线。
- 资产构建脚本：只做可重复的源素材切分与输出。

## 测试与验收

先写失败测试，再实现：

1. `ReadingScoreFeedback.spec.ts`
   - 玛丽使用加强爆炸；
   - 深海答错配置喷墨；
   - 诗词飞行物为纯毛笔且终点为墨水。
2. 新增墨鱼切分测试
   - 26 帧与 9/7/5/5 分布；
   - 等尺寸输出；
   - 墨滴未丢失。
3. 角色布局测试
   - 美食 `deer.y = -235`；
   - 其他主题坐标不变。
4. 视觉 E2E
   - 玛丽炸弹抵达积分处；
   - 深海左/中/右三列喷墨命中人物头部；
   - 美食待机多帧脚底接触；
   - 诗词纯毛笔飞行与终点墨水；
   - 五主题正反馈不回归。
5. 发布前
   - `typecheck`、相关 Jest、完整 E2E、`build:web`；
   - 检查构建包包含新雪碧图与纯毛笔；
   - 上传 COS、刷新并校验 CDN 哈希；
   - 只更新 `develop.h5Url` 并上传新的开发版小程序，`trial`/`release` 保持不变。

## 回滚

所有改动均按主题隔离。若某个主题视觉验收不通过，可单独恢复对应配置或视图，不影响计分、答题或其他主题。
